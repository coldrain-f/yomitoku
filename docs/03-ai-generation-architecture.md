# AI生成アーキテクチャとフロントエンド構成

## AI生成タスク

管理者のリクエストではタスクだけを即時に作成し、コストが発生する処理は別ワーカーが実行します。

```text
生成リクエスト
  -> queued
  -> generate
  -> validate_schema
  -> verify_answer + verify_quality
  -> decide
     -> revise または retry_generate
     -> ready_for_review / held / failed
```

- 生成タスクは`Idempotency-Key`とユーザーごとの実行中タスク再利用によって重複を防ぎます。
- AI生成問題では1つの設問と4つの選択肢を作成します。手動問題は種類に応じて複数設問に対応します。
- 受講者に表示する選択肢はシャッフルされるため、生成解説と誤答解説では選択肢の番号・位置に言及してはいけません。
- 検証を通過しても自動公開しません。生成された問題は管理者レビューを経て`published`になります。
- 構造化JSONが途中で切れた、または形式が合わない場合は、限られた出力再試行の後に`failed`として記録します。

## プロバイダーとプロンプト

- `generation_prompts.py`: プロンプトとトークン上限の定数
- `generation_provider.py`: 共通の結果・利用量型、コスト計算、Stubプロバイダー、factory
- `anthropic_generation_provider.py`: Anthropic SDKの呼び出しとJSON Schema応答の解析

デフォルトの`stub`プロバイダーは、外部コストをかけずに生成・検証・UIフローを検証します。`anthropic`プロバイダーはサーバーにのみ置かれたAPIキーを使います。モデルIDと許可モデル一覧は、運用環境変数で管理します。

## 記録と安全策

- `generation_jobs`には、リクエスト条件、状態、現在ノード、モデル、プロンプトバージョン、エラー、生成問題を記録します。
- `generation_usage_events`には、段階ごとの入力・出力・キャッシュトークン、コスト、中断理由を記録します。
- `item_validations`には、正答・品質検証の状態、スコア、issue code、根拠を記録します。
- 生成リクエストは管理者だけが実行できます。APIキー、JWTシークレット、DBパスワードをフロントエンドやGitHub Pagesに置きません。

## フロントエンド構成

Reactアプリは、機能別フォルダーと小さなフックを使用します。

- `features/auth`: ランディング、Googleログイン、現在ユーザー
- `features/readings`: 一覧・フィルター、試行復元、提出、ハイライト、翻訳
- `features/admin`: 一覧・編集・手動登録・生成・生成履歴
- `lib/api.ts`: APIリクエスト・レスポンス変換とエラーコード処理
- `lib/i18n.tsx`: 日本語・韓国語UI翻訳とAPIエラーメッセージ翻訳

サーバーデータは画面ごとのフックから取得し、ダイアログ、選択、トーストのように短いライフサイクルの状態だけをReact状態に置きます。新機能は、まず該当機能フォルダーのフック・コンポーネント・回帰テストに追加します。
