# 화면 및 사용자 흐름 명세

## 1. 공통 규칙

### 1.1 역할과 노출 범위

| 역할 | 접근 가능 범위 | 접근 불가 범위 |
| --- | --- | --- |
| 비로그인 | 공개 독해 목록, 제목 검색, 난이도/유형/정렬 필터 | 풀이 시작, 풀이 상태 필터, 결과, 통계, 관리자 |
| 학습자 | 공개 목록, 풀이, 결과, 통계, 오류 제보, 문항 평가 | 관리자 |
| 관리자 | 학습자 전체 범위와 관리자 문항 관리, 생성, 검토, 편집 | 없음 |

프론트는 역할에 따라 버튼과 화면을 숨긴다. 서버는 같은 권한을 API에서도 반드시 검사한다.

### 1.2 헤더와 이동 경로

- 좌측 `読み解く`은 로고이자 목록 이동 버튼이다.
- 목록 화면에서는 로고 클릭 시 즉시 목록을 유지한다.
- 풀이 중 로고 클릭 시 `풀이를 포기할까요?` 확인 다이얼로그를 연다. 확인하면 현재 답안과 시간은 저장하지 않고 목록으로 이동한다.
- 로그인 상태 헤더에는 관리자 링크(관리자만), `완료 수 / 생성된 전체 문항 수`, 로그아웃 아이콘을 표시한다.
- 비로그인 상태 헤더에는 로그인 링크만 표시한다.
- `완료 수 / 전체 문항 수`의 분모는 삭제되지 않은 생성 문항 전체 수이며, 게시 여부와 관계없다. 퍼센트는 헤더에 표시하지 않는다.
- Breadcrumb는 현재 화면을 표시한다. 목록, 통계, 풀이, 결과, 문항 관리, 문항 편집, 지문 생성, 미리보기를 구분한다.
- 목록, 통계, 관리자 화면 사이의 일반 이동은 즉시 처리한다. 단, 제출 전 풀이 중에는 이동 전에 포기 확인 다이얼로그를 연다.

### 1.3 공통 다이얼로그

다이얼로그는 배경 스크롤을 잠그고, 스크롤바 너비만큼 레이아웃을 보정해 본문이 흔들리지 않아야 한다.

- 닫기 버튼, 취소, 배경 클릭, `Esc`로 닫을 수 있다.
- 열기 전의 포커스로 복귀한다.
- `Tab`과 `Shift+Tab`은 다이얼로그 안에서 순환한다.
- 파괴적 동작의 취소 버튼 문구는 `취소`다.
- 문항 시작, 제출, 진행 중 풀이 포기, AI 지문 생성, 게시, 삭제, 오류 제보, 평가, 필터 조건 입력에 사용한다.
- 일반 화면 이동, 결과에서 목록 이동, 로그아웃, 생성 미리보기에서 관리 목록 이동에는 확인 다이얼로그를 사용하지 않는다.
- 문항 편집 화면은 저장하지 않은 편집 내용이 있을 때만 이탈 확인 다이얼로그를 연다.

## 2. 학습자 화면

### 2.1 독해 목록

목적은 공개된 문항을 찾고 풀이를 시작하는 것이다.

#### 표시 항목

- 제목
- 실제 난이도: `N5`부터 `N1`
- 체감 난이도: 유효 평가 10명 이상이면 `체감 N3`처럼 표시한다. 미만이면 `체감 집계 중`으로 표시한다.
- 유형: 단문, 중문, 장문
- 주제
- 등록일: `등록 YY.MM.DD`
- 로그인 사용자에게만 풀이 상태: 미풀이, 정답, 오답
- 등록 후 72시간 이내 문항에 `신규` 배지

체감 난이도 평가 인원은 일반 목록에 표시하지 않는다. 관리자 목록과 편집 상세에서만 확인할 수 있다.

#### 검색, 필터, 정렬

- 제목 검색은 입력 즉시 적용한다. 일본어 제목을 포함 검색한다.
- 설정 아이콘은 다이얼로그에서 다음 조건을 선택하게 한다.
  - 난이도: 전체, N5, N4, N3, N2, N1
  - 유형: 전체, 단문, 중문, 장문
  - 풀이 상태: 전체, 미풀이, 오답, 정답. 로그인 사용자에게만 노출한다.
  - 정렬: 등록일 최신/오래된 순, 실제 난이도 낮은/높은 순, 체감 난이도 낮은/높은 순
- 체감 난이도 정렬에서 집계 중인 문항은 항상 마지막에 둔다.
- 활성 필터나 기본값이 아닌 정렬이 있으면 설정 아이콘에 적용 상태를 표시한다.
- 검색 또는 필터 결과가 없으면 빈 상태와 `필터 초기화`를 보여 준다.

#### 페이지네이션

- 페이지네이션은 결과가 1건 이상이면 항상 표시한다. 데이터 수가 적어도 첫 페이지 버튼을 표시한다.
- 기본 페이지 크기는 10개다.
- 이전/다음 버튼, 현재 페이지, 첫/마지막 페이지, 생략 기호를 제공한다.
- 페이지 이동 뒤 목록 툴바로 부드럽게 이동한다.

#### 시작 흐름

1. 비로그인 사용자가 문항을 누르면 로그인 다이얼로그를 먼저 연다.
2. 로그인 완료 후 같은 문항의 시작 다이얼로그를 연다.
3. 로그인 사용자가 문항을 누르면 시작 다이얼로그를 연다.
4. 오답 문항은 `오답 문항을 다시 풀까요?`, 정답 문항은 `문항을 다시 풀까요?`를 표시한다.
5. 시작 확인 후 풀이 시간이 시작되고 풀이 화면으로 이동한다.

### 2.2 풀이 화면

#### 표시 항목

- 실제 난이도, 체감 난이도 또는 집계 중, 유형
- 제목
- 권장 시간과 경과 시간. 권장 시간은 단문 01:00, 중문 02:30, 장문 04:30을 기본값으로 사용하며 문항별 값이 우선한다.
- 지문, 질문, 사지선다 선택지
- 오류 제보, 포기하기, 제출하기

#### 선택지와 제출 규칙

- 문항마다 선택지의 영구 ID를 가진다. 화면에서 보이는 `01`~`04` 번호는 영구 ID가 아니다.
- 풀이를 새로 시작할 때마다 선택지 표시 순서를 무작위로 섞는다.
- 키보드 화살표와 `Home`, `End`로 선택지를 이동하고 선택할 수 있다.
- 선택지 없이 제출을 누르면 화면 안에 안내 문구를 표시한다.
- 선택지를 고른 뒤 `제출하기`를 누르면 확인 다이얼로그를 연다.
- 서버 제출 성공 후 같은 화면에서 즉시 다음을 표시한다.
  - 선택한 답이 정답이면 정답 배경, 오답이면 오답 배경
  - 정답 선택지 표시
  - 모든 선택지 비활성화
  - `NN이 정답인 이유` 해설
  - 오답일 때 `내가 고른 NN이 오답인 이유`
- 제출하기와 포기하기를 숨기고 `다음으로` 버튼을 표시한다.
- `다음으로`는 결과 화면으로 이동한다.

#### 포기와 오류 제보

- 포기하기는 제출하기 왼쪽에 둔다.
- 포기 확인 후에는 시도 기록을 만들지 않는다. 이미 서버에 시작 기록을 만들었다면 `abandoned_at`만 기록하고 통계에는 포함하지 않는다.
- 오류 제보는 다른 화면으로 이동하지 않고 다이얼로그에서 제보 내용을 입력해 전송한다. 빈 내용은 전송하지 않는다.

### 2.3 결과 화면

제출 직후 문항의 결과를 요약한다.

- 제목, 유형, 실제/체감 난이도, 주제
- 결과: 정답 또는 오답
- 내 답과 정답의 화면상 번호
- 유형 기준 권장 시간, 실제 풀이 시간, 권장 시간 초과 여부
- 이 문항의 정답률과 도전한 고유 사용자 수
- 문항 평가, 다음 문항 또는 다시 풀기, 목록으로 버튼

`다음 문항`은 다음 공개 문항을 시작하는 확인 다이얼로그를 연다. 오답이면 `다시 풀기`로 표기하고 같은 문항을 새 시도로 시작한다.

문항 평가는 다이얼로그에서 다음을 모두 선택해야 제출할 수 있다.

- 문항 품질: 매우 아쉬움, 아쉬움, 보통, 좋음, 매우 좋음
- 체감 난이도: N5부터 N1
- 선택 사항: 개선 의견

### 2.4 학습 통계

로그인 사용자만 접근한다.

- 상단 요약: 풀이 완료 수/전체 생성 문항 수, 전체 정답률, 평균 풀이 시간
- 전체 진도 막대
- 유형별: 생성 문항 수 대비 완료 수, 정답률, 평균 풀이 시간
- 난이도별: 생성 문항 수 대비 완료 수, 정답률, 평균 풀이 시간
- 페이지 길이가 긴 경우 우측 플로팅 위/아래 이동 버튼을 표시한다.
- 화면에는 집계 기준을 명시한다. 세부 계산은 [02-data-and-api-spec.md](./02-data-and-api-spec.md)를 따른다.

## 3. 관리자 화면

### 3.1 문항 관리 목록

관리자 헤더의 `관리자`는 즉시 문항 관리 화면으로 이동한다. 단, 제출 전 풀이 중에는 포기 확인 다이얼로그를 거친다.

각 문항은 다음 정보를 표시한다.

- 제목, 실제 난이도, 체감 난이도와 평가 인원, 유형, 주제
- 상태: 검토 중, 보류, 게시
- 등록일과 수정일

제목 검색과 설정 다이얼로그를 제공한다.

- 필터: 난이도, 유형, 주제, 상태
- 정렬: 수정일, 등록일, 제목, 실제 난이도, 체감 난이도, 상태
- 체감 난이도 정렬은 집계 중 문항을 마지막에 둔다.

문항을 누르면 편집 화면으로 이동한다. `새 독해 지문 생성`은 생성 화면으로 이동한다.

### 3.2 문항 편집

편집 가능 항목은 제목, 실제 난이도, 유형, 주제, 지문, 질문, 선택지 4개, 정답, 해설이다.

함께 표시하는 읽기 전용 운영 정보는 다음과 같다.

- 체감 난이도와 응답 수, 공개/비공개 여부
- 문항 품질 평균, 체감 난이도, 오류 제보 수, 최근 오류 제보
- 생성 검증 결과: 정답 검증, 오답 설계, 해설 논리

동작 규칙은 다음과 같다.

- 저장: 편집 내용을 저장하고 수정일을 갱신한다.
- 보류: 검토 중 또는 게시 문항을 보류로 전환한다. 게시 문항을 보류로 전환하면 즉시 학습자 목록에서 제외한다.
- 보류 취소: 보류 문항을 검토 중으로 전환한다. 보류 취소만으로 자동 게시하지 않는다.
- 게시하기: 검토 중 문항만 게시할 수 있다.
- 삭제: 확인 다이얼로그 후 영구 삭제한다. 삭제 후 복구 UI나 휴지통을 제공하지 않는다.
- `관리 목록으로`: 저장하지 않은 편집 내용이 없으면 즉시 이동하고, 있으면 변경사항을 버릴지 확인한다.

### 3.3 새 독해 지문 생성과 미리보기

생성 입력은 난이도, 유형, 주제다.

- 난이도: N5~N1
- 유형: 단문, 중문, 장문
- 주제: 추천(랜덤), 생활, 사회, 경제, 과학, 기술, 문화, 여행, 요리, 게임, 교육, 환경
- 후리가나: 미표기만 가능. 표기는 비활성화한다.

`지문 만들기` 확인 뒤 생성 API를 호출하고, 완료되면 생성된 문항 검토 화면으로 이동한다. 바로 학습을 시작하지 않는다.

미리보기에는 지문, 질문, 선택지, 정답, 해설을 모두 표시한다.

- 보류: `보류됨`이 되고 게시하기를 비활성화한다. 다시 누르면 보류를 취소해 검토 중으로 돌아간다.
- 게시하기: 검토 중일 때만 가능하다. 게시 후 관리자 목록으로 이동한다.
- 삭제: 영구 삭제 후 관리자 목록으로 이동한다.
- 보류 상태에서는 `관리 목록으로`로 나갈 수 있다.

## 4. 상태 전이

| 현재 상태 | 동작 | 다음 상태 | 학습자 노출 |
| --- | --- | --- | --- |
| 검토 중 | 보류 | 보류 | 노출 안 함 |
| 검토 중 | 게시 | 게시 | 노출 |
| 검토 중 | 삭제 | 삭제됨 | 노출 안 함 |
| 보류 | 보류 취소 | 검토 중 | 노출 안 함 |
| 보류 | 삭제 | 삭제됨 | 노출 안 함 |
| 게시 | 보류로 전환 | 보류 | 즉시 제외 |
| 게시 | 삭제 | 삭제됨 | 즉시 제외 |

삭제됨은 화면에 남기는 상태가 아니라 데이터 삭제 결과다. DB에서는 문항과 연결된 선택지, 시도, 평가, 오류 제보, 생성/검증 기록을 한 트랜잭션으로 제거한다.

## 5. 반응형 및 접근성

- 모바일에서는 검색, 필터, 제목, 유형이 흐름을 깨지 않게 한 줄 또는 명확한 줄바꿈으로 배치한다.
- 목록 제목은 모바일에서 한 줄 말줄임표로 처리한다.
- 버튼과 아이콘 버튼은 고정된 최소 터치 영역을 유지한다.
- 아이콘만 있는 로그아웃, 필터, 닫기, 스크롤 버튼에는 `aria-label`과 툴팁을 제공한다.
- 선택지, 필터, 평가 버튼은 키보드 조작과 선택 상태(`aria-checked` 또는 `aria-pressed`)를 제공한다.
- 색상만으로 정답/오답/상태를 판단하게 하지 않고 텍스트와 구조를 함께 제공한다.
