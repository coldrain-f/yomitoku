# 구현 완료 점검표

아래 항목은 정적 시안의 재현 여부가 아니라 실제 서비스 동작의 완료 기준이다. 각 항목은 데스크톱과 모바일에서 확인한다.

## 1. 인증과 권한

- [ ] 비로그인 사용자는 목록과 공개 필터만 볼 수 있다.
- [ ] 비로그인 사용자는 문항을 누르면 로그인 확인 흐름을 거친다.
- [ ] 로그인 전에는 풀이 상태, 개인 통계, 관리자 링크가 보이지 않는다.
- [ ] 로그인 사용자는 자신의 풀이 상태와 통계를 볼 수 있다.
- [ ] 관리자 allowlist에 없는 로그인 사용자는 관리자 API와 화면에 접근할 수 없다.
- [ ] 관리자 allowlist의 사용자는 문항 관리와 생성 기능을 사용할 수 있다.
- [ ] 프론트에서 관리자 URL을 직접 열어도 서버 권한 검사를 우회할 수 없다.
- [ ] 로그아웃 후 보호 화면에 남지 않고 목록으로 이동한다.

## 2. 목록

- [ ] 게시 문항만 학습자 목록 API에서 반환한다.
- [ ] 제목 검색이 일본어 제목에 대해 즉시 동작한다.
- [ ] 난이도와 유형 필터가 동시에 적용된다.
- [ ] 로그인 사용자만 풀이 상태 필터를 볼 수 있고 사용할 수 있다.
- [ ] 등록일, 실제 난이도, 체감 난이도 정렬이 정확히 동작한다.
- [ ] 체감 난이도 미집계 문항은 체감 정렬에서 마지막에 표시된다.
- [ ] 일반 목록의 체감 난이도에는 인원 수가 표시되지 않는다.
- [ ] 유효 평가 10명 미만 문항은 `체감 집계 중`으로 보인다.
- [ ] 등록 72시간 이내 문항만 신규 배지를 보인다.
- [ ] 결과가 1페이지여도 페이지네이션이 표시된다.
- [ ] 빈 결과에서 필터 초기화로 정상 목록으로 돌아온다.
- [ ] 모바일에서 제목은 한 줄 말줄임표가 되고 행 레이아웃이 깨지지 않는다.

## 3. 풀이와 결과

- [ ] 시작 확인 뒤에만 풀이 타이머가 시작한다.
- [ ] 단문, 중문, 장문 권장 시간이 각각 01:00, 02:30, 04:30 또는 문항별 값으로 표시된다.
- [ ] 매 새 풀이에서 선택지 표시 순서가 섞인다.
- [ ] 제출 데이터는 화면 번호가 아닌 선택지 ID를 보낸다.
- [ ] 제출 전 상세 API와 화면에 정답 정보가 노출되지 않는다.
- [ ] 선택지 없이 제출하면 안내가 보이고 제출되지 않는다.
- [ ] 제출 확인 다이얼로그의 취소 버튼은 `취소`다.
- [ ] 제출 후 정답/오답, 정답 선택지, 해설이 같은 화면에 표시된다.
- [ ] 오답이면 선택한 오답 선택지의 설명도 표시된다.
- [ ] 제출 뒤 선택지를 바꿀 수 없고 제출/포기 버튼이 숨겨진다.
- [ ] 제출 뒤 다음으로 버튼이 표시되고 결과 화면으로 이동한다.
- [ ] 포기하면 제출 시도와 통계가 만들어지지 않는다.
- [ ] 오류 제보는 화면 이동 없이 다이얼로그로 제출되며 빈 제보는 막는다.
- [ ] 결과 화면에 내 답, 정답, 권장 시간, 실제 시간, 정답률, 고유 도전 수가 표시된다.
- [ ] 오답 결과의 다시 풀기는 새 시도를 만든다.

## 4. 통계와 체감 난이도

- [ ] 헤더는 `완료 수 / 전체 생성 문항 수`만 표시하고 퍼센트는 표시하지 않는다.
- [ ] 전체 생성 문항 수에는 검토 중/보류/게시 문항이 포함되고 영구 삭제 문항은 제외된다.
- [ ] 완료 수는 한 번 이상 제출한 고유 문항 수다.
- [ ] 정답률과 평균 시간은 문항별 최근 제출 기준으로 계산된다.
- [ ] 유형별과 난이도별 분모는 생성 문항 수다.
- [ ] 문항 정답률은 고유 사용자의 최신 제출을 기준으로 계산된다.
- [ ] 체감 난이도는 사용자별 최신 평가 10명 이상에서만 공개된다.
- [ ] 통계 페이지의 위/아래 이동 버튼이 긴 화면에서 작동한다.

## 5. 문항 평가와 오류 제보

- [ ] 문항 평가는 품질 5단계와 체감 난이도를 모두 선택해야 제출된다.
- [ ] 같은 사용자가 같은 문항을 다시 평가하면 최신 값으로 갱신된다.
- [ ] 관리자는 품질 평균, 체감 난이도와 응답 수, 오류 제보 수, 최근 제보를 볼 수 있다.
- [ ] 오류 제보는 문항 ID와 사용자 ID에 연결된다.

## 6. 관리자 문항 관리

- [ ] 관리자 목록에 제목, 난이도, 체감 난이도와 인원 수, 유형, 주제, 상태, 등록일, 수정일이 보인다.
- [ ] 관리자 검색, 필터, 정렬, 페이지네이션이 실제 서버 데이터에 적용된다.
- [ ] 관리자 편집에서 제목, 내용, 난이도, 유형, 주제, 선택지, 정답, 해설을 저장할 수 있다.
- [ ] 저장하면 수정일이 갱신된다.
- [ ] 편집 화면에 문항 반응과 생성 검증 정보가 표시된다.
- [ ] 검토 중 문항은 게시할 수 있다.
- [ ] 보류는 데이터를 남기고 학습자 목록에서 숨긴다.
- [ ] 보류 취소는 검토 중으로만 전환하며 자동 게시하지 않는다.
- [ ] 게시 문항을 보류로 바꾸면 새 학습 시작이 즉시 막힌다.
- [ ] 삭제 전에는 복구 불가 안내와 확인 다이얼로그가 보인다.
- [ ] 삭제하면 문항과 선택지, 시도, 평가, 제보, 생성/검증 기록이 모두 제거된다.
- [ ] 삭제 후 목록, 통계, 검색 결과, API에서 해당 문항을 다시 찾을 수 없다.

## 7. AI 생성

- [ ] 생성은 관리자만 요청할 수 있다.
- [ ] 난이도, 유형, 주제가 생성 요청에 포함된다.
- [ ] 후리가나 표기는 비활성화되고 서버도 지원하지 않는다.
- [ ] 생성 요청은 중복 클릭 또는 재시도로 같은 작업을 중복 생성하지 않는다.
- [ ] 생성 작업은 LangGraph의 영속 체크포인트와 작업 ID로 재시도·재개할 수 있다.
- [ ] 생성, 규칙 검증, 정답 검증, 품질 검증, 판정, 재생성의 노드 상태가 관리자에게 조회된다.
- [ ] 생성 결과는 처음에 검토 중 상태다.
- [ ] 정답 하나, 선택지 4개, 해설, 오답 설명을 규칙으로 검증한다.
- [ ] 정답 검증자는 정답을 사전에 보지 않고 독립적으로 답과 근거를 도출한다.
- [ ] 품질 검증자는 오답 설계, 문항 모호성, 해설 논리를 평가한다.
- [ ] 검증 불일치는 최대 2회까지만 재생성하고, 해결되지 않으면 보류 또는 실패로 종료한다.
- [ ] AI 검증 통과만으로 자동 게시되지 않고 반드시 관리자 검토를 거친다.
- [ ] 의미 검증 결과와 issue code가 관리자 화면에 남는다.
- [ ] 경고/실패 결과와 생성 오류를 관리자가 확인할 수 있다.
- [ ] 생성 비용, 토큰, 생성·검증 모델, 프롬프트 버전, 요청 조건이 기록된다.
- [ ] 생성 한도와 쿨다운이 서버에서 동작한다.

## 8. 공통 UX와 품질

- [ ] 다이얼로그를 열고 닫아도 본문 폭이나 위치가 움직이지 않는다.
- [ ] 다이얼로그에서 Esc, 배경 클릭, 닫기, 취소, 포커스 순환이 동작한다.
- [ ] 일반 화면 이동은 즉시 처리하고, 진행 중 풀이·파괴적 또는 비용 발생 동작에서만 확인 다이얼로그를 연다.
- [ ] 문항 편집 중 `관리 목록으로`와 헤더 이동은 항상 종료 확인을 거치며, 저장하지 않은 편집 내용이 있으면 변경사항 폐기 안내를 표시한다.
- [ ] 아이콘만 있는 버튼에 접근성 레이블과 툴팁이 있다.
- [ ] 키보드로 선택지, 필터, 평가를 조작할 수 있다.
- [ ] 로딩, 빈 상태, 권한 없음, 네트워크 오류, 서버 검증 오류를 각각 표시한다.
- [ ] 작은 모바일과 넓은 데스크톱에서 텍스트 겹침, 버튼 잘림, 가로 스크롤이 없다.
- [ ] API 오류가 발생해도 정답, 권한, 삭제 상태가 클라이언트에서 잘못 표시되지 않는다.
- [ ] React 전환 후 새로고침과 직접 URL 접근에서도 화면 상태가 서버 데이터와 일치한다.
