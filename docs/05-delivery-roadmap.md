# 현재 운영 단계와 개선 원칙

## 현재 상태

React 프론트엔드, Google 로그인, FastAPI·PostgreSQL, 관리자 문항 관리, AI 생성 워커, 북마크·하이라이트·통계, 한국어/일본어 UI, 운영 Compose 구성이 연결되어 있다. 서비스 구조와 자동 백엔드 회귀 테스트도 정리된 상태다.

프런트엔드는 화면 단위 코드 분할, 검색 디바운스·요청 취소·15초 제한, 현재 풀이 세션 복원, 북마크 되돌리기, 키보드 접근성, 전체 필터 기준 다음 미풀이 탐색까지 반영됐다. 이제 기능 범위를 늘리기보다 실제 브라우저와 로그인 계정으로 이 흐름을 검증하는 단계다.

현재 우선순위는 선제적인 파일 분리가 아니라 실제 사용자 QA다.

## 다음 운영 순서

1. [QA 체크리스트](./04-acceptance-checklist.md)의 학습자·관리자 핵심 흐름을 실제 기기에서 확인한다. 특히 느린 네트워크 검색, 풀이·결과 새로고침, 다음 미풀이 소진, 키보드 전용 다이얼로그 조작을 점검한다.
2. 재현 절차와 화면을 남긴 결함만 우선순위화한다.
3. 수정 범위에 맞는 프론트엔드 또는 백엔드 회귀 테스트를 추가한다.
4. 테스트·빌드·운영 health check를 통과한 뒤 배포한다.
5. 배포 뒤 로그인, 목록, 풀이 제출, 관리자 저장을 한 번씩 smoke test 한다.

## 개선 판단 기준

- 사용자가 반복해서 겪는 오류, 데이터 손실 가능성, 권한·결제·AI 비용 문제를 가장 먼저 고친다.
- 모바일 조작성, 다국어 문구, 느린 네트워크 로딩처럼 실사용에서 드러나는 문제를 다음으로 다룬다.
- 단순히 파일이 길다는 이유만으로 서비스 분리를 이어 가지 않는다. 새 기능 또는 반복 수정에서 책임이 실제로 충돌할 때만 리팩터링한다.
- 새로운 분석·추천·외부 연동 기능은 사용자 흐름과 운영 비용을 먼저 문서화한 뒤 도입한다.

## 완료 기준

한 개선은 재현 절차가 사라지고, 관련 자동 검증 및 수동 QA를 통과하며, 화면·API·운영 문서 중 영향받는 문서가 갱신됐을 때 완료로 본다.
