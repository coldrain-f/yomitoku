# 現在の運用段階と改善方針

## 現在の状態

Reactフロントエンド、Googleログイン、FastAPI・PostgreSQL、管理者向け問題管理、AI生成ワーカー、ブックマーク・ハイライト・統計、日本語・韓国語UI、運用Compose構成が接続されています。サービス構造とバックエンドの自動回帰テストも整備済みです。

フロントエンドには、画面単位のコード分割、検索デバウンス・リクエストキャンセル・15秒制限、現在の解答セッション復元、ブックマークの取り消し、キーボードアクセシビリティ、全フィルター条件に基づく次の未回答問題検索までを反映しました。今は機能範囲を広げるより、実際のブラウザとログインアカウントでこのフローを検証する段階です。

現在の優先順位は、先回りしたファイル分割ではなく、実際のユーザーQAです。

## 次の運用手順

1. [QAチェックリスト](./04-acceptance-checklist.md)の受講者・管理者の主要フローを実機で確認します。特に、低速ネットワークでの検索、解答・結果の再読み込み、次の未回答問題の枯渇、キーボードのみでのダイアログ操作を確認します。
2. 再現手順と画面を残せる不具合だけを優先順位付けします。
3. 修正範囲に対応するフロントエンドまたはバックエンドの回帰テストを追加します。
4. テスト・ビルド・運用ヘルスチェックを通過してからデプロイします。
5. デプロイ後に、ログイン、一覧、解答提出、管理者保存をそれぞれ1回ずつスモークテストします。

## 改善の判断基準

- ユーザーが繰り返し経験する不具合、データ損失の可能性、権限・課金・AIコストの問題を最優先で修正します。
- モバイルの操作性、多言語の文言、低速ネットワークでの読み込みなど、実使用で表れる問題を次に扱います。
- 単にファイルが長いという理由だけでサービス分割を進めません。新機能または繰り返す修正で責務が実際に衝突する場合にのみリファクタリングします。
- 新しい分析・推薦・外部連携機能は、ユーザーフローと運用コストを先に文書化してから導入します。

## 完了基準

改善は、再現手順が解消され、関連する自動検証と手動QAを通過し、画面・API・運用文書のうち影響を受ける文書が更新されたときに完了とします。
